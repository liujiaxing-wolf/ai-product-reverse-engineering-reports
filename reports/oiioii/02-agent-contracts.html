08 · CLAIM REGISTER

事实、推断和未知事项清单

页面事实

  • 艺术总监、编剧、角色设计师、场景设计师、道具设计师、分镜师及 Oii Agent 名称均可见。
  • 剧本、3 个角色图、场景资产、3 个道具结果、4 个分镜提示与 4 个视频卡在页面出现。
  • 道具设计师明确邀请分镜师加入群聊。
  • 用户有满意/修改、样片/全部、预览/剪辑/下载等选择。
  • 场景多视图缺失曾阻塞道具流程；最终又出现音效/BGM未完全生成警告。
  • 资产库为空与画布已有资产同时出现。

合理推断

  • Oii Agent 可能承担路由或会话编排，但页面不足以确认其为独立执行 Agent。
  • 艺术总监配置被编剧及下游读取；编剧脚本又被角色、场景、道具和分镜使用。
  • 从“全部准备就绪”可推断场景多视图后来大概率被补齐，但没有直接修复结果截图。
  • 画布连线可能表达引用或依赖关系，但不能证明存在稳定资产 ID。
  • 分镜师在样片确认后被再次调用，且承接了视频生成能力。

尚未确认

  • 官方工具名、参数、模型调用日志、隐藏思维链、完整 System Prompt。
  • 长期用户偏好、历史项目、Face ID、音色库、权限是否被 Agent 读取。
  • 上游修改后下游资产是否自动失效、重跑或保留多版本。
  • 生成失败、余额不足、安全拦截、用户中断后的状态机与费用策略。
  • 音效/BGM与最终合成由谁负责；最终视频是否真正满足需求。
  • 聊天、任务、画布和资产库中哪一个是权威状态源。
09 · NEXT VALIDATION

最值得继续验证的五个问题

这些问题能最大幅度降低 Agent 契约的不确定性，也直接影响同类产品的状态一致性、成本透明度与可恢复性设计。

  1. 上游修改会怎样传播？
    修改剧本或角色后，观察分镜与视频是否标记过期、自动失效、产生新版本或重新扣费。
  2. 失败与余额不足由谁接管？
    刻意触发生成失败或余额不足，记录错误组件、负责 Agent、重试入口、费用回滚和已有资产保留。
  3. 场景多视图补偿的真实闭环是什么？
    完整记录“发现缺失→调用生成→资产出现→状态更新→道具恢复”的每一步与证据。
  4. 跨页面资产是否有稳定引用与单一真相源？
    刷新、重开项目并编辑资产，检查画布连线、资产库、聊天状态、任务状态及历史版本是否一致。
  5. 谁负责音效、BGM、最终合成和质量验收？
    完成最终预览，确认是否新增 Agent、具体输入输出、完整性门槛，以及“已完成”是否由实际可播放结果验证。
本轮停止点：报告止于 Agent 契约、工具与全局上下文假设，不继续编写完整 System Prompt。下一步应先由使用者核对 Agent 的输入、输出、工具和上下文边界。
